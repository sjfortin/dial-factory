# FI-002 — validate the delivered UI artifact

Status: PROPOSED; factory policy changes require review.

Problem: DIAL-001's build and metadata checks passed while the delivered inline JavaScript was corrupted by replacement-string substitution. The owner discovered a blank ChatGPT player with indefinite opening text.

Evidence: Verify run run-9211b8b34599 reproduced 19 HTML doctype insertions and a JavaScript syntax error at candidate c4122ec7. Callback insertion preserved the bundle and parsed successfully. See the work-item report and evidence/verify-9211b8b34599/resource-assembly.json.

Proposed improvement: add a targeted delivered-artifact check to the MCP UI verification skill/contract: fetch the actual registered resource and validate script syntax, rather than relying on build output or metadata alone. Preserve actual host behavior as a separate gate. This proposal does not modify production factory rules.

Why the factory missed it: implementation and review inspected registration, bridge markers and controller tests; prior verification read metadata without parsing the assembled script. The transport test asserted a bridge substring, which survived corruption.

Measure: future UI tasks should include delivered-artifact evidence and distinguish it from host rendering/audio evidence. One observed incident; no recurrence claim.

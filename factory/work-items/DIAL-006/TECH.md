## Architecture and data

- Keep `find_stations_by_country` as the initial tool. Add one bounded server tool for the next page, with input limited to an assigned country code and page index 1 or 2 (offsets 50 and 100); reject other values. Never accept a URL, host, arbitrary offset, or page size from the caller. Existing Radio Browser origin validation, HTTPS-only provider fetch, no provider redirect, 5-second timeout, 512 KB response cap, 50-row scan and sanitized station fields apply to every page. At most ten accepted rows are returned per page.
- Give page responses a clear kind/country/page index and scanned count so the UI can distinguish a continuation from a new country result. In `src/player.ts`, only a genuine new-country result calls `clearSelection`; a continuation updates list state without touching `src/player-controller.ts` or `src/playback-coordinator.ts`. Ignore stale responses for a different country or page request. Prevent concurrent More requests and repeated completed-page loads. Do not treat a provider failure as page completion.
- Keep a maximum of 30 rows in `src/station-list.ts` or a small catalog-state helper. Deduplicate by lowercase UUID and exact validated canonical URL (`new URL(...).href`); retain provider order and selection by UUID. Derive summary, button enablement, and selected visual state from that state. Preserve safe text-node rendering and row URL validation. A page with zero compatible rows may still lead to the next bounded page. Do not change selected audio source or coordination on append.
- Keep click tokens server-signed, bound to the Radio Browser UUID and short lived. Report only after a user-initiated play reaches the controller's existing playing threshold; reporting remains best effort and never changes audio. Page continuation must not mint tokens for synthetic stations or permit arbitrary UUID reporting. Retain provider attribution and privacy wording.
- Version the country UI resource URI when client script/HTML changes. Keep `connectDomains` empty and derive `resourceDomains` from the exact server media-origin list. The fixed player remains scoped to its existing Radio Paradise origin. Ensure server and client origin lists match exactly, preferably via a shared generated module or an automated equality check.

## Finite media policy

Accept only direct `https:` media URLs with no credentials, explicit port, fragment, playlist extension, or redirect to an unlisted origin. Codec remains Radio Browser `MP3`; direct response should be `audio/mpeg` and begin with plausible MP3 frame/ID3 bytes under a bounded read. Keep the existing origins `stream.radioparadise.com`, `audio.bfmtv.com`, and `media-ssl.musicradio.com`. The only origin additions this approval permits are `ice5.somafm.com` (US), `streamer.radio.co` (CA), `icy.unitedradio.it` (IT), `radiomeuh.ice.infomaniak.ch` and `novazz.ice.infomaniak.ch` (FR), plus conditional investigation candidates `liveradio.swr.de` or `stream.0nlineradio.com` (DE), `stream.gensokyoradio.net` or `stream.zeno.fm` (JP), and `playerservices.streamtheworld.com` or `stream.zeno.fm` (ES). All entries are HTTPS origins; the shared `stream.zeno.fm` origin is one entry. An origin is included only after a direct URL at that origin meets the checks and the host media policy allows it. No wildcard, arbitrary provider origin, URL fetch endpoint, stream relay, or CSP blanket domain is allowed.

The measured US SomaFM `secretagent-128-mp3`, CA Choice Classic Rock `s66f2626b4/listen`, IT Italia 70 `um020.mp3`, Meuh `radiomeuh-128.mp3`, and Nova `novazz-128.mp3` returned HTTP 200/206, `audio/mpeg`, and MP3-looking bytes with redirects disabled on 2026-11-06. This establishes reachability at probe time, not user audibility. The sampled DE SWR, JP Gensokyo, and ES Los 40 URLs returned 302/301/302 respectively; do not add those URLs unless an explicitly allowed direct endpoint is established. A small exact-UUID override for Meuh/Nova may replace their Radio Browser HTTP `url_resolved` with the tested HTTPS URL; never upgrade arbitrary HTTP provider URLs and keep their provider UUID for click attribution. FIP AAC at `icecast.radiofrance.fr/fip-hifi.aac` returned 200 `audio/aac`, outside the approved MP3 policy. Do not add AAC or the FIP origin without a new spec approval.

## Failure and rollback

Provider outages or invalid pages return bounded error results; the UI retains loaded rows and current playback and permits retry. Media failure shows the existing retryable player error. If an added origin redirects outside policy, fails host CSP, or is not playable, remove that candidate from the implementation and document the gap. If the approved country coverage cannot be achieved within this finite set, seek a new approved revision. Revert the candidate commit to the prior reviewed behavior if pagination or policy changes regress playback. No merge, publication, hosting, or deployment occurs in this phase.

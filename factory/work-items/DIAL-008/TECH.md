# DIAL-008 — bounded collected catalog and client reveal

## Approval and architecture

Foreman obtains owner approval of the exact SHA-256 revisions of this file and PRODUCT.md before Implement edits production code. Base work on the current DIAL-007 branch. Keep discovery server-side and the current country resource inside the MCP App. Replace page-length-based client continuation with one bounded server collection per country request, followed by local reveal in batches of eight. The UI receives only known compatible choices. This deliberately changes the previous per-page More behavior; no speculative continuation is needed.

## Server, API and data

- In `src/discovery.ts`, reuse the current country normalization, exact Radio Browser origin, `boundedJson`, row filtering, finite media policy, UUID overrides, and signed five-minute click tokens. Fetch offsets 0, 50, and 100 in order, with `limit=50`, `order=votes`, `reverse=true`, and `hidebroken=true`. Each request retains the 5-second deadline, 512 KB response cap, redirect rejection, and at-most-50-row processing. Attempt all three windows regardless of raw page length, earlier failure, or reaching the choice cap. This bounds an automatic scan to three requests, 150 examined rows, 30 returned choices, and at most 15 seconds of provider deadlines when sequential.
- Filter all 50 rows in each fetched window until the global 30-choice limit, rather than truncating to ten before cross-window deduplication. Maintain canonical lowercase UUID and parsed canonical media URL sets across windows. Preserve provider order, sanitized name/metadata, exact-country MP3 rule, approved HTTPS origins, and the existing exact UUID overrides. Create click tokens for returned accepted rows; avoid server-side media probes.
- `find_stations_by_country` returns one structured catalog: `kind: 'initial'`, `countryCode`, `status`, `stations` (0–30), `windows` (each attempted page index, offset, searched row count, and success/failure), `scanState: 'complete' | 'partial'`, and `choiceLimitReached: boolean`. `complete` means all three windows succeeded; `partial` means at least one failed. The choice-limit flag is separate because a failure and a full 30-choice buffer can coexist. For a partial scan, continue to the next bounded window so successful later windows still contribute. `status` is `ok` when any compatible choice exists, `provider_unavailable` when no choice exists and any window failed, `no_stations` only when a complete scan saw zero raw rows, and `no_supported_stations` only when a complete scan saw raw rows but no compatible choices. Invalid country makes no provider request and has no scan state. Never turn a failed window into a no-results/exhausted assertion.
- Retire `more_stations_by_country` as the client continuation path. Add an app-only `retry_stations_by_country` tool with an assigned country-code input and the same bounded collector. Its structured result is `kind: 'retry'`, so uncorrelated host `ontoolresult` notifications cannot replace the active initial catalog. Update the visible tool description and country resource URI for the changed response/UI contract. Do not add provider/media origins, CSP permissions, arbitrary offsets, or hosting endpoints. Keep the fixed-player resource and click-report tool behavior.

## Client state and guards

- In `src/station-list.ts`, store a validated, deduplicated buffer of at most 30 rows and a visible count. Validate each row with the current `safeRow` policy before it can enter the buffer; dedupe by lowercase UUID and canonical URL even if a malformed server response repeats them. Show `min(8, count)` after an initial result. More is `visibleCount < buffer.length`, and each click increments visible count by `min(8, remaining)` synchronously. No provider call or Play action occurs on More. Summary text distinguishes scanned/collected/visible counts, complete versus choice limit versus partial, and avoids a blanket directory-exhaustion claim.
- In `src/player.ts` and `public/discovery.html`, use a separate Retry scan button only for `scanState: 'partial'`. Capture the current catalog generation, country code, and retry request identity before calling the retry tool. Consume its matching `kind: 'retry'` promise result; ignore uncorrelated retry notifications, old generations, old countries, and duplicate completion. Retain existing buffered rows in order and append valid fresh unique rows into remaining slots up to 30; visible rows and the selected marker stay in place. Do not call `player.clearSelection()` or change audio for More or Retry. On retry failure, keep existing choices and the incomplete state, and allow another manual retry. On a retry whose scan succeeds, remove the Retry control; on another partial result, retain it. On a genuinely new initial country result, clear selection as today and increment generation; an outstanding retry cannot later mutate it.
- Ensure an initial tool response has the new contract before replacing the catalog. Failure to parse it must yield a visible load error rather than silently claiming no stations. A retry may add zero choices; that is a truthful retry outcome, not More. Preserve safe DOM text rendering, keyboard buttons, Studio colors/layout, attribution, best-effort click reporting after actual playback, and existing playback/stale guards.

## Failure and rollback

Partial provider failure is recoverable by explicit Retry scan; each retry is a new user-initiated scan subject to the same per-scan request/row/choice bounds, with no automatic retries or background polling. A complete scan with no compatible choices is a finite result for these windows only. The choice-limit flag states the cap, not full coverage; it may coexist with a partial scan. Playback errors remain independent of catalog eligibility. Correct a regression through Implement, fresh independent Review and Verify. Roll back the candidate commit to the reviewed DIAL-007 behavior if the new collection/reveal contract regresses playback or host compatibility; no merge, publication, deployment, or hosting occurs here.

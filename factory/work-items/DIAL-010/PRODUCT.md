# DIAL-010 — experimental NTS playback in Dial

## Problem and decision

Dial shows NTS 1 and NTS 2 but offers only links to the NTS site. The owner wants a focused, reviewable test of whether these live channels can play inside Dial's ChatGPT MCP App. The existing DIAL-009 rule requires host proof before enabling NTS Play, which prevents the host test itself. **For this experimental NTS UI only, this spec supersedes that pre-enable gate:** build an explicit Play path using the finite observed route, then test it in the real host. It does not assert that playback already works or approve a general NTS media policy.

The owner's read-only Omarchy NTS client uses `https://stream-relay-geo.ntslive.net/stream` and `/stream2`; its single mpv process follows the geo redirect, reports failures, and reconnects live audio. [NTS's published direct-player links](https://ntslive.freshdesk.com/support/solutions/articles/77000587257-tunein) append `?client=direct`. Dial will use those published links, its existing single browser `<audio>` element, and the existing playback coordinator. mpv success does not establish browser or ChatGPT success.

## Behavior and UX

- The current compact Countries/NTS panel remains. NTS 1 and NTS 2 stay separate NTS editorial channels, with their official-site links visible. An “Experimental in-player playback” note states that availability depends on this host and network. The NTS rows are selectable; selection prepares a channel but never starts audio. The main button enables Play for an NTS selection.
- Explicit Play attempts the selected official HTTPS stream. Pause stops the audible element; pressing Play again attempts audible playback of the selected channel. “Resume” means audio is heard again, not a guarantee of a particular live-edge position. Switching channels or selecting a country station stops the previous stream before another can play. Changing tabs alone does not start or stop audio. Existing one-instance/other-thread coordination continues to apply.
- An NTS playback failure, including a changed redirect destination blocked by CSP, stops the attempt and shows a concise “stream unavailable or blocked” status. The selected channel and its **Open on NTS** link remain usable; the user may retry with Play. The UI does not claim to diagnose CSP from a generic media error. A blocked or unsupported host does not silently start server-side streaming or another player.
- NTS is not a Radio Browser result: it has no country/codec assertion, click token, Radio Browser click report, or country attribution. Prior country selection and disclosure behavior remain intact. A new country search and all Radio Browser admission rules remain as in DIAL-009.

## Boundaries and edge cases

This is a two-channel experiment for the tested ChatGPT host, browser profile, date, and network vantage. It is not a claim of worldwide availability or durable edge stability. No NTS search, schedule, artwork, accounts, favorites, persistence guarantee, automatic reconnect, media proxy, server-side stream fetch, broad wildcard CSP, deployment, merge, or publication. A transient CDN hostname may change; the defined outcome is a clean error plus official link. Host audio permission, redirect/CSP, or coordination failure must remain visible instead of being inferred from HTTP status. Keep keyboard focus, narrow and desktop layouts, and light/dark presentation usable without introducing a second player surface.

## Acceptance

1. **Reference and route evidence.** Record the actual reference URL/backend/error behavior, NTS's published exact NTS 1/2 URLs, and dated redirect/status/content-type observations for both channels. Distinguish the owner client, direct HTTP, browser, and ChatGPT host evidence. Record the test profile and network vantage; do not claim global reliability.
2. **Bounded in-app experiment.** NTS 1/2 selection and explicit Play/Pause/Play-again use the existing audio controller and coordination. The NTS media source is fixed to the two published URLs. The UI resource declares only the three currently observed NTS route origins in addition to its existing country origins; no wildcard, proxy, or `connectDomains` expansion. A changed or blocked destination yields an honest error and working official link. Automated checks cover exact URLs/CSP, selection and source switching, NTS not reporting Radio Browser clicks, Play/Pause/resume, error fallback, and existing country behavior.
3. **Independent candidate and host outcome.** Independent Review and Verify inspect the same candidate commit. Verify separately records direct HTTP route, local browser behavior if obtainable in a bounded run, and actual ChatGPT UI/CSP plus audible NTS 1 and NTS 2 Play, Pause, and Play-again, including an error path and coordination. Each layer may PASS, FAIL, or BLOCKED based on its own evidence. If real host access or audible observation is missing, host playback and the overall technical outcome remain **BLOCKED**, even if code, HTTP checks, and local tests pass. A host failure is recorded as FAIL rather than represented as working playback.

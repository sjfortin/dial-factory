# DIAL-010 — narrow NTS media experiment

## Architecture and exact media policy

Keep `find_stations_by_country`, Radio Browser filtering/click reporting, and the existing `public/discovery.html` panel, `src/player.ts`, `src/player-controller.ts`, one `<audio>` element, and `src/playback-coordinator.ts`. Add an NTS source distinct from a catalog row. Its only media URLs are the two [NTS published direct-player URLs](https://ntslive.freshdesk.com/support/solutions/articles/77000587257-tunein):

| Channel | Exact `<audio src>` |
| --- | --- |
| NTS 1 | `https://stream-relay-geo.ntslive.net/stream?client=direct` |
| NTS 2 | `https://stream-relay-geo.ntslive.net/stream2?client=direct` |

The owner reference's `Model.js` uses the same paths without the query; `Player.qml` uses one mpv process that follows the 302 redirect, exposes paused/loading/error state, and retries dropped live streams. These are design context, not browser evidence. No reference files are changed or copied into Dial.

On 2026-11-12 from this shell/network vantage, Triage's bounded manual-redirect probe observed each official URL return `302` to `https://streams.radiomast.io/nts1` or `/nts2`, then `302` to `https://audio-edge-kkqan.sin.d.radiomast.io/nts1` or `/nts2`, then `200 audio/mpeg`. Spec repeated both routes at **08:29 UTC**, with an 8-second timeout per hop, `Range: bytes=0-63`, manual redirects and a five-hop cap, and observed the same route/status/content type. This is two times at one network vantage, not a stability promise. Neither probe decoded audio or exercised ChatGPT. Triage's bounded Chromium attempt produced no browser result within 30 seconds.

Only the NTS-enabled discovery resource's `_meta.ui.csp.resourceDomains` gains these **three exact origins**: `https://stream-relay-geo.ntslive.net`, `https://streams.radiomast.io`, `https://audio-edge-kkqan.sin.d.radiomast.io`. Keep the pre-existing country origins and `connectDomains: []`. Give the changed discovery resource a new URI/version so the host does not reuse cached DIAL-009 content. MCP Apps' [CSP type](https://github.com/modelcontextprotocol/ext-apps/blob/main/src/spec.types.ts) maps `resourceDomains` to media resources; the host still determines enforcement. CSP grants origins, not exact paths: fixed source URL constants and no arbitrary NTS URL input constrain what Dial initiates. The browser may follow redirects; Dial cannot inspect or approve each hop in `<audio>`. If an unlisted edge is chosen, CSP is expected to block it and the player must show the fallback. Do not add a wildcard, alternate edge, proxy, or server fetch based solely on one failed test; that requires a new reviewed spec and evidence.

## Components and data flow

- `src/player.ts` and `public/discovery.html`: select NTS 1/2 from the existing panel, mark the selected row, set NTS title/subtitle and experimental note, and call `player.selectStation` with a fixed NTS URL and **no** `clickToken`. This enables the existing explicit main Play button. Keep official links visible even while selected or in error. Country attribution is hidden for NTS; it remains correctly shown for selected Radio Browser stations. Selection and tab switching do not autoplay.
- `src/player-controller.ts`: reuse existing Play/Pause/Play-again, media error, stale-event guards, and coordinator. If the current generic error hides the useful NTS fallback, add a source-aware status string without relaxing country handling. A failed promise, media `error`, or coordination failure must release ownership and leave Play available for a deliberate retry. Avoid an automatic retry loop; the reference's mpv retry policy is not a requirement for this short browser experiment.
- `src/server.ts` and a small NTS policy module or constants: expose only the exact two official URLs to the UI and the three observed NTS resource origins in the discovery resource CSP. Do not extend `src/media-policy.ts`'s Radio Browser `parseMediaUrl` admission to NTS or add NTS to `MEDIA_ORIGINS` used for provider filtering. No NTS server tool or persisted data is needed.

## Verification plan and evidence boundaries

1. Build/typecheck and focused tests: NTS constant-to-channel mapping; exact CSP list and empty `connectDomains`; no wildcard or arbitrary NTS source; selected NTS is idle until Play; Play/Pause/Play-again and NTS1↔NTS2 or NTS↔country switching use one element and coordinator; stale events do not restart old audio; media/coordination error gives retry and official link; NTS never invokes `report_station_click`; DIAL-009 country discovery/admission and attribution regressions remain green. Tests may mock audio but must not be called audible proof.
2. Repeat a finite direct HTTP probe of each published URL with manual redirects, per-hop deadline and hop cap. Capture date, vantage, each URL/status/Location/content type, and bounded bytes if consumed. Report changed paths/edge honestly. This is route evidence only.
3. If a local browser test is available, use a bounded run with an explicit user gesture and capture media events plus CSP console/network evidence; stop after a fixed timeout and record BLOCKED if no result. Do not spend unbounded time setting up headless audio. Local browser success does not stand in for ChatGPT.
4. After an authorized test endpoint/connection is available, refresh the ChatGPT MCP App resource and record host/client/browser profile, date, network geography/vantage, delivered resource URI/CSP, and observed redirect/CSP console or network evidence where accessible. For **each** channel, select, Play, confirm audible sound, Pause, confirm silence, then Play again and confirm audible sound. Check NTS1→NTS2 and NTS→country selection stop the former stream, other-thread coordination where the host allows a second instance, and a blocked/error path with the official link. Distinguish direct observation from host instrumentation that is unavailable. Missing host access, audible observer, or CSP inspection is BLOCKED for the relevant subcheck; do not mark it PASS from direct HTTP or unit tests. Independent Verify accounts for all three work-item criteria and binds the current candidate commit.

## Failure and rollback

An unlisted redirect edge, audio rejection, or absent host support leaves the NTS UI selectable but reports “unavailable or blocked” and keeps **Open on NTS** reachable. The finite CSP cannot guarantee continued playback outside the tested vantage/profile. For a changed edge, capture the new route and host result; do not silently add it. If the experimental NTS change breaks the country player or leaks Radio Browser reporting, revert the candidate to the independently accepted DIAL-009 link-only behavior and remove the three added NTS CSP origins. Any broader CDN admission or intermediary is a separate approval. No merge, publish, or deploy is part of this work item.

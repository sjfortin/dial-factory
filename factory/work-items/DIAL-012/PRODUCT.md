# DIAL-012 — Country radio, NTS, and archive controls

## Problem and outcome

Dial currently opens a combined country/NTS player. NTS archive episodes cannot be searched in Dial, and the user must remember how to reopen a player to pause it from another thread. Give country radio and NTS distinct, directly invokable experiences; make common requests visible; add bounded NTS show/episode search and pursue in-app archive playback with evidence from the actual ChatGPT host. This is one shared Dial playback system.

The owner reports current live radio works. That evidence does not establish archived-show audio. As of 2026-11-13, NTS metadata search and one SoundCloud HLS route were observed outside the host; audible archive playback inside ChatGPT remains unverified.

## Behavior and UX

1. **Entry points.** `open_country_radio` opens a country-first player with the country chooser/results visible. `open_nts_radio` opens an NTS-first player with NTS 1, NTS 2, and archive search visible. Neither requires choosing a tab first. A compact action in each view opens the other experience. Both use the same playback owner and remote-pause status. Changing views within a mounted app does not start or stop the current audio; selecting another source does stop it. A host may unmount a prior app when opening a new one, which stops that app's audio. The distinct views share one canonical app resource to preserve browser coordination. Existing `find_stations_by_country`, `open_radio`, and all previously registered country resource URIs remain compatible, with the same country admission and current NTS live policy.
2. **Discoverability.** Each view has a labeled Help control that expands a short, keyboard reachable list of copyable natural-language examples. Tool titles/descriptions route the model to the same operations. Examples are “Dial, open country radio”, “Dial, find stations in Japan”, “Dial, open NTS”, “Dial, play NTS 1”, “Dial, search NTS archives for Floating Points”, and “Dial, pause”. These are examples of requests, not registered slash commands or guaranteed model behavior. The help text says to press Play in the displayed app to start audio.
3. **NTS live.** NTS 1 and NTS 2 are direct choices in the NTS view. A request to “play NTS 1” opens the NTS view with channel 1 selected and a visible Play button; it never asserts that the model can bypass browser gesture rules. Existing live URL, error, ownership, and external NTS link behavior continues.
4. **Archive search.** A keyword query, such as a show or episode name, returns at most 12 NTS show/episode results in a bounded first page. Search is available from the NTS view and via a model-visible `search_nts_archive` tool that opens the same NTS view with the query/results. Results show title, show, date when supplied, type, and a valid NTS episode/show link. Selecting a show exposes up to 12 recent episodes in the same view. An episode without an approved audio source remains discoverable with a clear “Audio unavailable here” state and its NTS link. Empty, incomplete, changed-provider, and unavailable states are distinct and retryable; metadata alone never earns a “Playable” label.
5. **Archive playback.** An episode with a validated, browser-compatible direct media candidate can be selected, then played only by pressing Play in the app. Display title, Play/Pause, elapsed/total time where available, and a simple seek control only when the media reports a finite seekable range. On pause, preserve the position in the currently mounted app; Play resumes there. Selecting another episode starts that episode at 0. On ended, Play restarts at 0. Reload/new thread may require fresh search and starts at 0; no account or durable listening history. A signed URL expiry or network/media failure produces a clean error and a Retry action that resolves a fresh URL; never silently play a different episode. If the host or format cannot play, show an honest unsupported state and the official NTS link. NTS link fallback is not completion of archive playback.
6. **Pause from another thread.** A model-visible `pause_dial` opens a small control UI that attempts one pause of the reported active Dial player when mounted in a thread in the same tested browser profile/device. It shows confirmed ack, no player found, timeout/unconfirmed, or unsupported coordination, and offers a visible Pause button to retry. It does not claim server-wide or cross-device control. Both main views retain their remote Pause button and status. A model response alone is not a pause confirmation.

## Scope and non-goals

The archive target is public NTS show/episode metadata and public SoundCloud-hosted audio that can be validated for in-app playback. Mixcloud and other audio hosts remain discoverable through official NTS links until their media formats, CORS, origins, and host behavior receive separate evidence and policy approval. No arbitrary URL input, generic audio proxy, login, credential reuse, cookies, download, queue, favorites, recommendations, supporter-only tracklist timestamps, cross-device identity, background daemon, or hidden playback. Do not copy source files from the owner’s native Omarchy NTS repository; it is read-only reference material.

## Edge cases

Reject blank/overlong queries and malformed result paths. Handle duplicate results, missing/unsafe source URLs, absent or infinite duration, nonseekable streams, concurrent searches and play requests, stale signed URLs, browser autoplay rejection, media errors, thread closure, ownership transfer, and remote pause ack timeout. Show status in text as well as icon/color. Do not reveal signed media query values in logs, error text, help, or durable records. Archive metadata and provider formats may change without notice because the NTS API is undocumented.

## Acceptance

1. Country and NTS each have a model-visible tool and separate default view; cross-links and Help are visible, keyboard usable, and screen-reader labeled. Historical country aliases still render and country/NTS live playback regressions are checked.
2. The six example requests above lead to the intended tool/view in observed host traces or their routing limits are recorded. `pause_dial` outcome derives from a real same-browser acknowledgement, not a server assertion.
3. A bounded NTS search returns show and episode results with safe links; show selection lists bounded episodes. Empty/error/source-unavailable states are visible. NTS metadata provenance and unofficial API status are disclosed compactly.
4. At least one public NTS archive episode plays audibly inside the ChatGPT MCP App after explicit Play, pauses, resumes, and seeks when seekable, with actual host evidence for media URL, CSP/CORS, format, and ownership. If this cannot be verified, mark archive playback **BLOCKED**, preserve the working entry/search/control deliverables, and name the exact failed boundary. An external NTS link alone does not pass this criterion.
5. Archive source trust restrictions, expiring URL handling, no signed-query logging, and current live/country origin policies pass independent Review and Verify.

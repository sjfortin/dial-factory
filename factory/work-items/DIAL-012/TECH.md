# DIAL-012 — Technical proposal

## Architecture and entry points

Keep the TypeScript MCP server and static, bundled app resources. Register `open_country_radio` (optional ISO alpha-2 country), `open_nts_radio` (optional channel `1` or `2`), `search_nts_archive` (required keyword), and `pause_dial` (no input) as model-visible tools. Bind all four to **one new canonical UI resource URI** so the browser origin needed for Web Locks/BroadcastChannel coordination is shared. The server tool result carries a discriminated `launchMode` (`country`, `nts`, `nts-search`, `pause-control`) and any validated query/channel; the renderer shows a distinct country-first, NTS-first, or compact pause-control view. This is separate user-facing entry and default content, not a mandatory tab choice. Retain `find_stations_by_country` and all historical country URI registrations as compatibility aliases serving the current country default; do not silently repoint them to NTS. `open_radio` remains the one-station proof. Check in the actual host that the new canonical resource and historical aliases share the browser coordination scope before claiming cross-thread control. Tool descriptions include example language and the explicit in-app Play requirement. App-only tools handle search/show detail/episode resolution from within the NTS view; the model-visible search tool uses the same bounded server function. Tool outputs contain normalized metadata, never raw untrusted API objects.

The resource CSP is fixed per resource, not per `launchMode`. Put the archive media origin on the new canonical resource and on each historical country alias that serves the same renderer, even when the country-first view is showing. This grants a network permission to the shared renderer, but does not change country station admission or the existing live NTS URL policy. The one-station proof resource remains separate.

`pause_dial` returns a fresh request ID with `launchMode: pause-control`. On receiving that tool result, the mounted control attempts exactly one `PlaybackCoordinator.pauseRemote()` call and reports its existing acknowledgement/timeout state; a button permits user retry. A repeated mount/result with the same request ID cannot issue a second automatic pause. If the host does not mount the app or coordination is unavailable, no server-side pause claim is made. The existing Web Locks/BroadcastChannel protocol is shared across country, NTS live, archive, and control views. The control view never acquires ownership or plays audio. The observed scope is threads in one browser profile/device where these browser capabilities are shared.

## NTS metadata contract

Use HTTPS `https://www.nts.live/api/v2` only, fixed endpoint paths and server-constructed parameters. First search: `/search` with `version=2`, `types[]=show`, `types[]=episode`, `offset=0`, `limit=12`; trim keyword to 1–120 Unicode characters and reject control characters. Show episode list: `/shows/{validatedAlias}/episodes?limit=12&offset=0`. Episode detail: `/shows/{validatedShowAlias}/episodes/{validatedEpisodeAlias}` only after a returned selection. Exact alias grammar: lowercase ASCII letters, digits, and hyphens, 1–100 characters; no slash, dot segment, encoding, port, userinfo, or free-form URL. The search result’s `article.path` must exactly match the expected show or episode path before extracting aliases. Normalize and cap title (120), show name (120), date (40), description snippet (240) and result count. This API is undocumented, so schema validation failure is a provider error, not an empty result.

Server fetches use `redirect: error`, an 8-second deadline, 256 KiB maximum response, JSON content-type check, and at most one in-flight request per UI action. A new search cancels/ignores older results. No unbounded pagination, crawl, or server-side archive index. Cache normalized search/show metadata in memory for at most 5 minutes if useful; no user identity or listening history. These numeric caps are proposed defaults for this exact revision.

## Media resolution and trust policy

The owner’s native reference is informative: `NtsApi.js` parses NTS `audio_sources`, allows SoundCloud/Mixcloud pages, and `Resolver.qml` invokes `yt-dlp` for progressive formats. Dial’s browser cannot execute that subprocess; the existing Node server on this machine can invoke installed `/usr/bin/yt-dlp` only for a selected, server-fetched public NTS episode. Do not call NTS `/resolve-stream` or use embedded credentials.

Bind every resolution to validated show/episode aliases, re-fetch that episode’s metadata, and choose an HTTPS `soundcloud.com` page from its `audio_sources`. Reject private/IP/localhost hosts, userinfo, nondefault ports, fragments, path tricks, and URLs over 600 characters. Do not accept a model/user supplied media URL. Spawn yt-dlp with an argv array, `--ignore-config`, no playlist/cookies/browser profile, no download, no shell, one resolution at a time per request, socket timeout 8 seconds, zero retries, process deadline 30 seconds, 16 KiB stdout/stderr caps, and termination on timeout. Select a single audio format; permit direct progressive MP3/AAC or HLS AAC only. Never expose its diagnostics or signed URL in logs. No durable resolved-URL cache; use a candidate in memory for at most 5 minutes and re-resolve on Retry or when its parsed `expires` timestamp is within 60 seconds. If `expires` is present but invalid or already expired, reject it.

As of 2026-11-13, two sampled Floating Points episodes did not expose a progressive format through the native selector. One 2024 episode exposed only AAC HLS formats. `yt-dlp` selected an `m3u8_native` AAC playlist on `https://playback.media-streaming.soundcloud.cloud` with query keys `Key-Pair-Id`, `Policy`, `Signature`, `expires`; values were not retained. A bounded playlist read returned HTTP 200, CORS `*`, same-origin sampled segment references, and a sample segment HEAD returned HTTP 200, CORS `*`, `audio/mp4`. This is a viable **candidate path**, not proof of browser-host playback or general archive coverage. [hls.js](https://github.com/video-dev/hls.js) documents MSE playback for audio-only HLS; Implement must pin one exact hls.js release in `package-lock.json`, bundle its light build, and report that version before Review. Enable it only if the target host exposes suitable MSE and the candidate works in an actual MCP App. Native HLS via media element may be used when supported. No CDN script loading.

The initial archive CSP addition is exactly `https://playback.media-streaming.soundcloud.cloud` in **both** `connectDomains` and `resourceDomains` for the shared canonical renderer and its historical aliases. `connectDomains` covers HLS manifest/segment fetches; `resourceDomains` covers direct media fallback. Keep current country `MEDIA_ORIGINS` and current NTS live `NTS_RESOURCE_ORIGINS` unchanged; do not add wildcards. An MSE `blob:` media URL may depend on host CSP behavior not established by server metadata; verify it in the actual host and report a block if disallowed, rather than silently expand policy. If a validated resolved candidate has any other origin, unsupported scheme, unsupported codec/container, manifest reference to another origin, or unapproved redirects, reject it and show the episode’s NTS link. Do not automatically broaden CSP or add a proxy. Before enabling a candidate, check the returned URL’s origin, path shape `/.../playlist.m3u8` for HLS, length (at most 2000), format, signature expiry when present, and manifest/segment reference origins. Browser fetches should fail closed on CSP/CORS or MSE errors. The origin/path observation is a scoped initial admission policy, not an assurance that future SoundCloud URLs match.

Only the active app instance receives an ephemeral resolved media URL through an app-only resolver tool result's `_meta` payload. The signed URL must be absent from model-visible `content` and `structuredContent`, app model context, widget state, and any logs. It stays in app memory until stopped/disposed or expires; scrub it from state on teardown and never write signed query values to console, analytics, reports, or persistence. Verify the host actually forwards this app-only `_meta` payload to the mounted app before relying on it; otherwise mark playback blocked rather than expose the token in another channel. The NTS link is a validated `https://www.nts.live/shows/{show}/episodes/{episode}` URL. The browser contacts SoundCloud media only after the user selects and presses Play. The server's resolver may contact SoundCloud on that gesture-driven app request. No generic media relay endpoint.

## Player state and failure behavior

Extend the shared player state with source mode (`country-live`, `nts-live`, `nts-archive`), selected ID, play attempt/abort epoch, and archive duration/currentTime/seekability. Preserve existing coordinator ownership and stale-attempt guards. On Play for an archive episode, acquire or transfer ownership, resolve a fresh URL if needed, attach native HLS or hls.js, then call media `play()` from the explicit app action. If async resolution loses the browser gesture and autoplay rejects, retain a prominent Play button and instruct a second press; never auto-retry invisibly. Selecting another source cancels resolution, stops media, destroys hls.js, releases ownership, clears URL, and resets archive position. Changing country/NTS **view only** within a mounted app preserves the current player and audio. A host unmount still invokes normal teardown. Pause retains current mounted episode position and URL until expiry; resume after expiry resolves again, seeks to saved position if seekable, and requires a user Play action. Seek control is disabled until finite duration and seekable ranges exist; clamp seek to the valid range. Live pause/resume rejoins the current stream. `ended` resets archive position to 0. Errors preserve selected title and official link and never report “Playing”.

No headless or network workaround beyond the stated origin. If this fails at origin/format boundary, stop expansion and report the boundary.
3. Independently Review and Verify the candidate commit. Verify actual ChatGPT host rendering, explicit Play and audible archive media, Pause/seek/resume, same-browser cross-thread control, prompt routing, and errors. Protocol/Chromium fixture evidence cannot replace missing ChatGPT host evidence. Where host access is unavailable, report BLOCKED for the precise criterion and seek the minimum owner observation through Foreman.

Rollback is to remove the new tools/canonical resource and archive-only CSP/dependency while retaining historical aliases and existing live/country paths. Disable the archive candidate path independently if provider formats or origin behavior change; archive search and official episode links still work. Do not merge, publish, or deploy automatically. Every production change requires Foreman-recorded exact spec revision approval first.

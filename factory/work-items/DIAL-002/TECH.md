# DIAL-002 — technical proposal

## Architecture and data path

Extend the DIAL-001 TypeScript MCP server and existing inline audio UI. Add one model-visible `find_stations_by_country({countryCode})` tool linked to a versioned MCP Apps resource. The server validates a checked-in ISO 3166-1 alpha-2 set (pin the set and document its source/version), queries Radio Browser over HTTPS, normalizes records, filters eligibility, and returns concise text plus `structuredContent`. The UI consumes **that same returned array** and its stable `stationuuid`; Select stores the chosen array item in the current iframe and assigns exactly its validated `streamUrl` to the one audio element. It does not perform a second station lookup or accept a model-supplied URL. Thus the label, selected UUID, and audio source all come from one normalized record. Retain the existing `open_radio` proof path unless an approved migration explicitly supersedes it.

The tool response uses `{status, countryCode, searchedCount, limit: 50, stations}`. Each station has `{id, name, countryCode, streamUrl, origin, codec?, bitrate?, clickToken}`. IDs are Radio Browser `stationuuid`; duplicate IDs are removed. Names are trimmed and length-limited; missing names become “Unnamed station.” Country code must equal the requested code after normalization. The UI uses `textContent`, not HTML insertion, for every dynamic field and never loads station favicons/homepages. The text content is useful even in MCP clients without a UI and states when stations are unsupported by this proof.

The server calls a single configured Radio Browser HTTPS API origin, using `/json/stations/bycountrycodeexact/{code}?order=votes&reverse=true&offset=0&limit=50&hidebroken=true`. Send an identifying User-Agent, require a successful JSON array, cap response bytes, and abort after about five seconds. No retry cascade or mirror discovery in this phase; configuration/availability failures are explicit. Filter to at most ten rows with a nonempty valid UUID and name, exact matching country, `https:` URL with no credentials, and an **exact** origin in the reviewed list: `https://stream.radioparadise.com`, `https://audio.bfmtv.com`, `https://media-ssl.musicradio.com`. Use provider `url_resolved` when present, otherwise `url`; accept only direct MP3 records for the initial proof and exclude HLS/playlist records. Parse URL with the platform URL parser, reject nonstandard ports and URL fragments, and never interpolate it into HTML. The list is startup configuration with these three reviewed defaults, a hard cap of eight exact origins, and no catalog-driven expansion; it is copied verbatim to the resource's `resourceDomains`. Adding or replacing an origin changes the approved spec/CSP and needs review. `connectDomains` stays empty because only the server queries Radio Browser. The iframe audio element requests the stream directly. Redirects are not promoted into the allowlist; if a redirect needs another origin, a tested exact origin must be reviewed and added in a later revision. No wildcard CSP, origin derivation from arbitrary results, broad proxy, or server-side fetching of stream URLs.

This fixed resource policy is deliberate. OpenAI's current [MCP Apps UI guidance](https://developers.openai.com/plugins/build/chatgpt-ui) binds a UI resource URI through tool metadata and declares exact loaded-resource domains in the resource CSP. The current `registerAppTool`/`registerAppResource` path does not establish a per-search URI/CSP binding for concurrent calls. A shared resource whose CSP mutates to the latest search could mismatch a different user's result or a cached resource. We therefore filter catalog data against the registered policy. Host acceptance of media requests at each listed origin remains an actual ChatGPT test, not a conclusion from local metadata tests. Version the resource URI when its HTML/script/CSP changes and refresh the ChatGPT connection for host testing.

Use the existing player controller's audio element and state transitions, adding an explicit `selectStation` path: invalidate in-flight play attempts, pause, remove/reset previous source and media error, assign the chosen URL, show idle selected station, and require a new Play click. A late `playing`, `error`, or play-promise rejection from the previous source must not alter the new station's state. Preserve retry through `load()` after media errors and user-gesture-driven `play()`. A rapid switch while buffering is a required case.

## Click count and dependency policy

The [Radio Browser API reference](https://docs.radio-browser.info/) asks clients to call `/json/url/{stationuuid}` when a user starts a stream. Add a small app-only MCP tool that performs that provider request **after** a user-initiated Play reaches `playing`; do not use the endpoint's returned URL to change the chosen stream. Discovery attaches a short-lived, HMAC-SHA256 token over the station UUID and expiry to each normalized row. The server generates the signing key at process start; the click tool accepts only an unexpired valid token and derives the UUID from it, so arbitrary caller-supplied UUIDs cannot be forwarded. A process restart invalidates old UI tokens and leaves audio unaffected. This is best effort with a short timeout, no audio dependency, and no automatic background retry. Deduplicate for the same Play attempt; a later explicit resume can report another start, with Radio Browser's own daily per-IP cap. The provider sees the server IP and the station UUID/play event. Document this in the UI and README. Failure is logged without credentials/full URL and leaves playback running.

Dependencies remain the pinned MCP SDK/ext-apps, TypeScript, and esbuild. Use built-in `fetch`, `AbortController`, `URL`, and audio APIs; avoid a database or new UI framework. The checked-in ISO code set and configured origins are reviewed data, not silently expanded from provider responses. The provider station URL is passed only to the iframe; the server never requests it, preventing an audio-URL SSRF path. A format label is a hint, not a playback guarantee.

## Tests and verification

- Unit/provider fixtures: valid lowercase input normalization; unassigned code; no network on invalid input; exact query parameters; timeout/HTTP/bad JSON/oversize; empty country vs filtered unsupported; stable vote order, 50/10 caps, duplicate IDs, mismatched country, unsafe schemes/credentials/ports, unsupported formats, and hostile text. Test exact CSP equals the configured origin set.
- UI/controller tests: tool result rendering as text; select A then B; switch during buffering; stale async events; user gesture Play; Pause/resume; error/retry; denied redirect or incompatible media; no autoplay; and click reporting failure not affecting audio. Exercise two distinct station fixtures.
- End-to-end local MCP checks: `npm ci`, `npm test`, Inspector `tools/list`, valid/invalid/empty/provider-failure `tools/call`, and resource read. Parse the **delivered registered HTML's actual inline script** and test its bridge/selection behavior, addressing [FI-002](../../improvements/FI-002.md)'s DIAL-001 regression. Inspect returned CSP and ensure no dynamic provider origin leaks into it.
- The [2026-10-04 provider snapshot](evidence/spec-feasibility.md) supplies initial catalog feasibility. Before BUILDING, repeat the bounded query to confirm the exact origin list still yields at least two distinct eligible stations in each of FR and GB. If this gate fails, Foreman seeks a revised architecture decision or parks the work.
- Actual ChatGPT check on an authorized HTTPS `/mcp` endpoint: record a timestamped transcript/observation for two country requests, visible bounded rows, selection and audible Play/Pause/resume on two distinct eligible stations per country, switching behavior, CSP/network origin/redirect inspection, and routine new error outcomes. Record the tested stream URLs/origins and codecs. Inspector proves MCP behavior; only a human host observation proves audibility. If host media policy blocks an origin or streams fail, verification is BLOCKED/FAIL with evidence; do not claim universal compatibility. The deferred DIAL-001 controlled host error test stays separately deferred.

## Failure, rollback, and integration

Provider outage or timeout leaves a retryable discovery message. An absent eligible match is an honest constrained-result message, not an outage. Selected-stream errors leave the player operable; clicking another station resets it. If the new path fails after approval, revert the DIAL-002 product commit and restore the DIAL-001 `open_radio` behavior and its one-origin CSP; there is no persistent user data to migrate. Foreman must resolve PR #1 against the current default factory/bootstrap before BUILDING and choose whether to rebase/cherry-pick this stacked planning branch. No merge, deployment, or waiver rewrite is part of this specification.

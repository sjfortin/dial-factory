# DIAL-002 — country discovery and station selection proposal

## Problem and intended behavior

DIAL-001 proved one live stream can render and play inside the ChatGPT MCP Apps UI. A listener cannot yet find or choose another station. This phase lets a listener ask for stations using an ISO 3166-1 alpha-2 country code, inspect a small result set, select one, and use the existing Play/Pause/resume controls. The owner has approved preparation of this proposal only; these exact documents require approval before implementation.

The listener can say, for example, “Find radio stations in FR.” The model calls `find_stations_by_country` with `FR`. The response and inline player show **up to ten** eligible stations from the first **50** provider results, in the provider's vote-descending order. Each row shows station name, country code, and available codec/bitrate metadata; unknown metadata is omitted. The provider is credited as Radio Browser with a link to its API site. A row's Select button makes that station the current player choice and leaves it idle. Pressing Play then starts that station's HTTPS stream. Selecting another row stops the previous stream, clears its playback/error state, and requires another deliberate Play click. Pause and resume act on the selected station.

This is a constrained live-catalog proof. A station appears only if its direct HTTPS stream has an **exact origin in the reviewed media-origin allowlist** and its advertised format is one the implementation supports in the tested host. A valid country may therefore have no supported result even though Radio Browser lists stations there. The UI says “No supported stations in the first 50 results for XX” in that case; it never claims the country has no stations. The proposed initial origins are `https://stream.radioparadise.com` (DIAL-001 baseline), `https://audio.bfmtv.com` (FR), and `https://media-ssl.musicradio.com` (GB). A [dated catalog snapshot](evidence/spec-feasibility.md) found at least two distinct eligible MP3 stations in each of FR and GB within the stated first-50 query. That establishes catalog feasibility only; it does not establish ChatGPT media compatibility or audible playback. The allowlist is finite and published with the build, not expanded by catalog data. Before BUILDING, Foreman must recheck that the two-country/two-station feasibility still holds or return for a revised approved architecture. Actual-host evidence names the tested countries, stations, URL origins, formats, and dates. This proof does not promise coverage for every country or every HTTPS stream.

## Interaction and outcomes

- Country input is supplied conversationally to the MCP tool. There is no country picker or general search form. The tool trims and uppercases a code, then checks it against a checked-in ISO 3166-1 alpha-2 code set. Missing, malformed, or unassigned codes return an `invalid_country` outcome with an example such as `FR`; they do not call the provider.
- A successful query returns the normalized country code, bounded eligible rows, and a distinct status: `ok`, `no_stations` when the provider's bounded response is empty, or `no_supported_stations` when rows exist but none qualify. The interface displays the scope of the first-50 limit. It does not offer pagination in this phase.
- Provider timeout, HTTP failure, malformed response, or unavailable configured provider endpoint return `provider_unavailable` and a short retry message. They are not represented as empty results. A failed new query does not silently substitute old results for the requested country.
- Each Select button is clearly labeled with its station name. The selected name and playback state remain visible, and keyboard users can select a row and operate Play/Pause. Provider text is displayed as text, never as markup. No provider logo, embedded frame, or provider supplied link is loaded by the player.
- Playback begins only after a user presses Play. A rejected play promise, media error, blocked redirect, or incompatible/dead stream produces a selected-station error with a usable retry control; the listener can choose another row. A click-count reporting failure does not interrupt audio. Selection and playback state last only for that UI instance, as in DIAL-001.

## Boundaries

No favorites, account, database, personalized recommendation, name/genre search, station administration, NTS integration, pagination, audio proxy, arbitrary stream-origin support, production deployment, or background playback guarantee. DIAL-001's waived controlled **host** error-state check stays deferred in `docs/backlog.md`; DIAL-002 still requires understandable new input, discovery, and selected-stream outcomes.

## Acceptance contract

1. A valid ISO alpha-2 code invokes the country discovery tool and yields at most ten normalized selectable rows from at most 50 provider records. Invalid and unassigned codes are rejected before network access.
2. `no_stations`, `no_supported_stations`, and `provider_unavailable` are distinct in the tool result and UI. The UI states the first-50 coverage limit.
3. Selecting a result changes the current station and audio source, stops any previous stream, and requires a new Play click. Play, Pause, resume, retry, and rapid switch behavior work for a compatible, allowlisted HTTPS stream.
4. Only exact approved origins can be assigned to audio; arbitrary provider content cannot create markup or expand CSP. A redirect to an undeclared origin fails cleanly. The provider and click-count policy are disclosed.
5. Automated tests and MCP Inspector checks verify the tool contract, filtering/limits, delivered UI resource, and player transitions. Separate ChatGPT-host evidence records visible selection and **audible** play/pause/resume on two distinct stations in each of two countries; tool or Inspector success alone is insufficient evidence of host playback. If live provider changes prevent this, report the blocked criterion rather than substituting fixture evidence.

## Decisions requiring Foreman/owner approval

The key tradeoff is the **finite exact-origin media policy**. It limits countries and stations; a broader directory would need a separately reviewed media strategy. Exact owner approval should accept the three origins named above and this coverage limit, with the attached feasibility snapshot and a fresh prebuild check. This proposal also calls Radio Browser's click-counter endpoint on a successful user-initiated start, best effort, from the server: the provider receives the station UUID, play event, and server IP. Foreman should present that disclosure for approval. The pending DIAL-001 PR #1/default factory-bootstrap merge is an integration gate owned by Foreman, not an assumed completed baseline.
